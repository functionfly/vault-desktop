# Vault Desktop updater key fingerprint

> **Internal.** The real key paths, pubkey prefix, and fingerprint live in
> [`docs/INTERNAL.md`](../../docs/INTERNAL.md). This file is the pointer: it
> records *that* a key is live and *what to do about it*, without publishing
> the material itself.

This file is the operator-side source of truth for which
`VAULT_UPDATER_PUBKEY` value is currently live in production. Update
it whenever a key is rotated, and update
[`docs/INTERNAL.md`](../../docs/INTERNAL.md) at the same time.

## Current key

See the **Updater signing key** table in
[`docs/INTERNAL.md`](../../docs/INTERNAL.md).

Summary, deliberately without values:

- Algorithm: **Ed25519** (Tauri's default for `signer generate` since v2)
- Generated by: `cargo-tauri signer generate -w <path>` (cargo-tauri v2.12.1,
  installed via `cargo install tauri-cli --version "^2.11" --locked`)
- Private key, public key, and password file each live on the **build host
  only**, at the modes recorded in `docs/INTERNAL.md` (0600 / 0644 / 0400).
- The private key is also stored as the `TAURI_SIGNING_PRIVATE_KEY` GitHub
  secret. Nothing else may hold it.

## Verifying a build is signed

```bash
# On the build host, after a release build:
ls -l src-tauri/target/release/bundle/**/*.sig

# Compare the artefact's signature against the live pubkey:
cargo-tauri signer verify <path-to-artefact> \
  -k <key-dir>/vault-key.json.pub
```

A release with no `.sig` side-car is **not** publishable. `release.yml` fails
closed when `TAURI_SIGNING_PRIVATE_KEY` is absent precisely so an unsigned
artefact cannot ship by accident.

## Rotation procedure

1. **Do not overwrite the live key yet.** Generate a new pair alongside it:
   ```bash
   cargo-tauri signer generate -w <key-dir>/vault-key-v2.json
   ```
2. Update `VAULT_UPDATER_PUBKEY` on the build host and in the GitHub secrets.
   The plugin accepts the public key as a string **or** as a path to the `.pub`
   file; either form works.
3. Keep `bundle.createUpdaterArtifacts` enabled so the new artefact stays on
   the same channel URL. The plugin will verify both signatures until every
   client has rotated.
4. After a 30-day grace window (matching the R2 noncurrent-version lifecycle),
   delete the old key file.
5. Update this file **and** the table in
   [`docs/INTERNAL.md`](../../docs/INTERNAL.md).

> Never paste the private key, its password, or a full public key into a
> committed file, an issue, or a chat message. Point at `docs/INTERNAL.md`
> instead.
